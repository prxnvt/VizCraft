# `b6-sequence-ui`: sequence pages on the canvas (Block 6 wave 3 frontend)

Opus, medium effort. Port 8064. Worktree `.claude/worktrees/b6-sequence-ui`, branch `b6-sequence-ui`, cut from `claude/engineering-diagramming-standards-305d6b` after `b6e-frontend` merges. `CARGO_TARGET_DIR=target-b6-sequence-ui CARGO_INCREMENTAL=0`. Commit prefix `B6:`. Control channel on `127.0.0.1:8064` (`--control 8064`). Screenshots go under `/private/tmp/claude-501/b6-sequence-ui/`. Start the GUI with `VIZCRAFT_NO_PREFS=1` on the secondary monitor (`--window-pos -2500,100`), quit it with `app.quit`, and check with `pgrep -fl vizcraft`. Use the headless `ui_shot` example and kittest wherever a window is not essential.

**Goal.** Make a Sequence page (`Page.sequence`, wave 2) something a person can edit with the mouse and keyboard, not only with `sequence.*` ids.

- Lifelines are columns: they can be dragged sideways only, and they can be hit on the stem.
- Messages are rows. A drag reorders them through `sequence.move`. Drawing from stem to stem runs `sequence.addMessage` at the row under the pointer.
- Fragments wrap the selection, and their guards and operands can be edited.
- Activations are automatic by default, with explicit mode as a choice.
- A contextual Sequence tab and an Inspector Sequence group cover the rest.
- Message labels sit above their line on the canvas and in every export.

Every gesture ends in one command, so it is one undo step. The preview comes from the engine's own settle pass run on a copy of the page, so what you see while dragging is what you get.

## Scope

**Hit testing and overlays.**
- A lifeline is hit on its head or its stem: `sequence::stem_hit` is called from `hit::shape_contains` (an engine addition, below).
- A press on an activation bar or destruction mark picks its lifeline. The new `dg::sequence::owner(page, id)` is called first in `select.rs` `click_target` and `press_target`.
- Lifelines show no connection marks; all glue to a lifeline is dynamic.
- `drag.rs` `handle_allowed` and `rotate_allowed` return false for lifelines, fragments, bars and marks. Notes keep their resize handles, because their size feeds the layout.
- `takes_handles` skips any shape with `sequence: Some(_)`.
- The hover and selection outline of a lifeline is its head box plus an accent line along the stem.

**Drags.** One new variant, `Drag::Sequence(SeqDrag)`, defined in `canvas/interact/sequence.rs`. Each kind's preview is `dg::sequence::settle_page(&mut copy, true)` on an edited copy, unless stated otherwise.
- `Reorder {id, from, to}`: a Pointer press-drag on a message, note or fragment of a Sequence page.
  - Preview: `move_block` on the copy's events, then settle. An accent insertion line is drawn at the drop row.
  - Release runs `sequence.move {id, before|after|in}`, built from `dg::sequence::drop_position`.
  - A drop on the block itself, or one that changes nothing, runs nothing.
- `Column {id, from, to}`: a drag on a lifeline, horizontal only.
  - Preview: shift the copy's lifeline x, then settle. Columns reorder and get pushed apart live.
  - Release runs `shape.move {ids: [id], dx, dy: 0}`.
- `Message {from, y, to}`: the Connector tool pressed on a lifeline (head, stem or bar, through `dg::sequence::lifeline_at`) on a Sequence page.
  - No page preview. The overlay draws a straight rubber line at `y`, a self loop when it returns to the same stem, the target stem highlighted, and the insertion line.
  - Release on a lifeline runs `sequence.addMessage {from, to, sort, before|after|in}`, then opens the label editor (`start_editing(app, Hit::Connector(id))`).
  - The sort comes from `app.connector_kind` when it is one of the five `uml.*Message` types (matched through `Sort::connector_type`); otherwise it is `sync`. Lost and found are set from the Inspector.
  - A release on empty page shows a status message and runs nothing.
- `Separator {fragment, operand, from, to}`: a press within the grab distance of an operand's dashed separator.
  - Release runs one `edit.batch`: `sequence.removeOperand {id, operand}`, then `sequence.addOperand {id, before: <new first block>, guard: <old guard>}`. The target comes from `dg::sequence::separator_target`, bounded by the neighbouring separators.
- Regluing a message end keeps the existing `Reglue` drag. With dynamic glue to the new lifeline, settle moves the message.

**Creation.**
- `canvas/mod.rs` `insert_master` first asks `interact::sequence::insert_master(app, stencil, at)`. On a Sequence page it handles three masters:
  - `uml.lifeline` and `uml.actorLifeline` run `sequence.addLifeline {name: "Lifeline N", actor, at: column_at(x)}`, then edit the name in place;
  - `uml.note` runs `sequence.addNote {text: "Note", over: nearest lifeline, after|before: drop_position(y)}`, then edits it.
  - Palette clicks and drops both go through `insert_master`.
- `ui.sequenceLifeline {actor?}` inserts right of the selected lifeline (`at` = its column + 1), or at the end, then starts editing the name.
- `ui.sequenceNote {}` places a note over the selected lifeline, or over the selected message's receiver after that message.
- Wrap: the Sequence tab's operator menu runs `sequence.wrap {ids: <selected messages, notes, fragments>, operator}`. The engine's error (the gap or the nesting level) goes to the status bar.
- Add Operand runs `sequence.addOperand {id: <enclosing fragment>, before: <selected block>}`, using `dg::sequence::enclosing`.

**Editing.**
- A double-click on a fragment opens a one-line guard editor at the operand under the pointer (an `egui::Area` in `interact/sequence.rs`). Enter commits `sequence.setFragment {id, guards}`, with only that entry changed. Escape cancels. This is hooked by one line in `interact/mod.rs` before `start_editing_at`.
- Message labels use the existing connector editor, which follows `label_pos`. Lifeline names use the shape editor.
- Inspector "Sequence" group (body in `panes/sequence_section.rs`):
  - **message:** Sort combo (`sequence.setSort`); "Activate receiver" and "Deactivate sender" checkboxes (`sequence.setActivation`); its order index.
  - **fragment:** Operator combo, a guard row per operand with a remove button (`sequence.setFragment`, `sequence.removeOperand`), Covers checkboxes per lifeline (where empty means auto), and Unwrap.
  - **lifeline:** its column and "actor" (read only).
  - **nothing selected on a Sequence page:** Activations Auto/Explicit (`sequence.setActivations`); Row and Column gap fields (`sequence.layout {row, columnGap}`, which re-packs the columns, and the field says so).
  - The Net group is hidden for message connectors.
- Every choice here (activation mode, sort, operator, row, gap) is the user's, with the template's defaults: auto, sync, the menu's pick, 36 and 60.

**Labels above the line** (engine, so the canvas, SVG, PNG and PDF all follow):
- `dg::sequence::label_anchor(polyline, text, style)`: for a straight message, the label box's centre sits half its height plus 3 above the line's midpoint.
- For a self message (4 points) the label sits right of the loop, left-aligned at loop x + 4, at the loop's middle y. Lost and found labels go above their stub.
- The row height already reserves `label_h + 20` above the line (`layout/src/sequence.rs` `step`), so nothing moves.

**Sequence tab** (contextual, shown while `page.sequence.is_some()`), `ribbon/sequence/`. Each group is one file:
- **Lifelines:** Lifeline, Actor (`ui.sequenceLifeline`), Note (`ui.sequenceNote`).
- **Messages:** Sync, Async, Reply, Create, Destroy. Each is a toggle running `ui.tool {tool: "connector", kind: "uml.<sort>Message"}`, checked while armed. Reply runs `sequence.reply {call: <selected message>}`. Self Call runs `sequence.addMessage {from, to}` on the selected lifeline.
- **Fragments:** a Wrap menu with the 11 operators in catalog order (`Operator::ALL`), Add Operand, Unwrap.
- **Order:** Move Up, Move Down, Move Left, Move Right.
- **Activations:** Auto and Explicit toggles, Activate and Deactivate on the selected message.
- **Layout:** Lay Out (`sequence.layout`).
- Icons are drawn in code in `icons.rs`: `lifeline`, `actorLifeline`, `msgSync`, `msgAsync`, `msgReply`, `msgCreate`, `msgDestroy`, `fragment`, `operand`, `activation`.

**Keyboard.**
- Alt+Up and Alt+Down run `sequence.moveUp` and `sequence.moveDown` on the selected message, note or fragment.
- Alt+Left and Alt+Right run `sequence.moveLeft` and `sequence.moveRight` on the selected lifeline.
- None of them fire while a text field or in-place editor has the keyboard: the four ids are added to `keys.rs` `text_field_owns`.
- Delete removes a message, fragment (its content stays), note or lifeline, using the existing commands; settle prunes the events.
- Escape cancels any `Drag::Sequence`.
- Tab and Enter belong to `b6-ux` (see Risks).

## Risks and open questions

- **Preview cost.** Each frame of a `Reorder`, `Column` or `Separator` drag runs the layout on a page copy (at most 4096 events). Measure with `--trace` on a 500-message page. If it is too slow, fall back to the insertion line alone above some event count.
- **Two undo steps.** Add-then-name (message label, lifeline name) is two steps, as text-box creation is today. Folding them would need `edit.batch` with text typed before the add, which is out of scope.
- **`b6-ux` overlaps.**
  - Tab and Enter insertion and the `/` picker must skip shapes with a `sequence` part, or call this branch's `ui.sequenceLifeline` and `sequence.addMessage`. Agree on it at merge; `takes_handles` is the shared guard.
  - Double-click connector label editing must leave `label_pos` as the editor's anchor.
  - Both branches edit `inspector.rs`, `keys.rs` and `icons.rs` in different hunks.
- **Not built here (follow-ups):**
  - `autonumber` is stored but drawn nowhere;
  - note `over` and `side` have no editing command (`sequence.setNote`);
  - switching a lifeline to an actor, or marking it destroyed, has no command;
  - copying the page as Mermaid or PlantUML waits for `b6-code`'s Code pane;
  - message labels are always above the line. This is the UML convention, not a standards choice, so there is no option.
- **Adoption risk.** Adopting kind-typed message connectors could take in a hand-drawn connector that the user meant as plain drawing. Only `uml.*Message` kinds glued to two lifelines qualify.
