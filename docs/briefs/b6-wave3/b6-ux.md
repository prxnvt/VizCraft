# `b6-ux`: keyboard insertion, the relationship-aware picker, label editing, relationship and row editing (Block 6 wave 3 frontend)

Sonnet, medium effort. Control port 8069. Worktree `.claude/worktrees/b6-ux`, branch `b6-ux`, from the integration branch `claude/engineering-diagramming-standards-305d6b` once `b6e-frontend` has merged (the session names the commit). Run every cargo command with `CARGO_TARGET_DIR=target-b6-ux CARGO_INCREMENTAL=0`. Commit prefix `B6:`. Put screenshots under `/private/tmp/claude-501/b6-ux/`. Launch the GUI on the secondary monitor (`--window-pos -2500,100`), quit it through `app.quit` once you have looked, and check with `pgrep -fl vizcraft`. Prefer the headless `ui_shot` example and kittest. Read AGENTS.md in full before you start. Then read docs/cascade-plan.md "How Blocks 6 and 6E run" and "Block 6 wave 2" (its State paragraph), the Workspace changes section of docs/research/swe-diagramming-ux.md, and the "What a later frontend branch needs" sections of docs/briefs/b6-wave2/{b6-uml,b6-er,b6-topology}.md. Do not re-plan anything in docs/briefs/b6e-frontend/report*.md.

**Goal.** An engineer can build and edit a model-bound diagram from the keyboard and the panes without reaching for stencils:
- Tab adds the legal next element and Enter adds a sibling; typing names it.
- `/` opens the picker, which also offers relationships and patterns.
- A double-click edits a connector's label or an end label, such as a multiplicity.
- The Model Tree lists each element's relationships.
- The Inspector edits relationship ends, UML member rows and ER columns.
- The Design Re-Layout menu offers the notation's own layouts first.
- On notation pages the Process tab no longer repeats the notation tab's validation group.
- Cloud and C4 pages get the Key group and the Steps tool.

Every behaviour is a command first. Every notation choice (flow direction, layout) is a user choice with a default.

## Scope

**1. Keyboard insertion.** Files: `crates/ui-egui/src/keys.rs`, `canvas/interact/keys.rs`, the new `crates/ui-egui/src/notation_layout.rs`.
- **Canvas keys.** `keys::is_shortcut_key` treats bare Tab, Enter and `/` (no modifiers) as canvas keys, under the same `bare_letters_ok` gate as R/X/Y/W/P. Rename the doc wording from "bare letters" to "canvas keys". Extend the `combos_match_registry_spelling` and `every_registered_shortcut_is_reachable_from_a_key` tests: the latter's key list gains `Key::Tab`, `Key::Enter` and `Key::Slash`.
- **New `UI_COMMANDS` rows:**

| Command | Key | What it does |
|---|---|---|
| `ui.insertNext` | Tab | Params `{direction?}`. Returns the `insert.next` result. |
| `ui.insertSibling` | Enter | |
| `ui.editText` | F2 | Params `{id?}`; edits the selected shape or connector text. F2 is free in the registry. |
| `ui.insertDirection` | none | Params `{direction: auto\|right\|down\|left\|up}`. Returns `{direction, resolved}`. |
| `ui.insertPicker` | `/` | Existing row; it gains the shortcut. |

- **Tab.** With one shape selected, Tab runs `insert.next {id, direction: flow}` and then `edit_text::start_editing` on the returned `shape`. Typing names it, Enter commits (`shape.setText`, which renames a bound element) and Escape leaves it unnamed. That is two undo steps ("Insert Next Step", "Edit Text"); say so in the doc comment. Tab again continues the chain from the new shape. With no shape or several shapes selected, the status bar says "Select one shape to continue from".
- **Enter is a sibling, as in mind-map tools.**
  - With one shape selected: find the source shape of the first connector whose `end` glues to it. Run `insert.next {id: that source, direction: flow, type, relationship}`, where `type` is the selection's element type (else `suggest::stencil_of`) and `relationship` is that connector's relationship type. Then start naming, as Tab does.
  - With no predecessor, Enter edits the shape's text.
  - With one connector selected, Enter edits its label.
- **Flow direction.** Order of precedence:
  1. `UiState.insert_direction` (serde default `"auto"`, persisted with the preferences).
  2. On auto, the first template in `pack.templates` whose `viewpoint` is the page's viewpoint and whose `layout.direction` is set (TB is down, LR right, BT up, RL left).
  3. Otherwise right, which is `insert.next`'s own default.

  `notation_layout::flow_direction(app)` holds this rule, next to `layout_choices(app)` (part 8).
- **Sequence pages.** On a page with `Page.sequence` set, Tab and Enter do nothing here; `b6-sequence-ui` owns keyboard flow there. Keep the guard in one function, `notation_layout::sequence_page(app)`.

**2. The `/` picker with relationship, connect and pattern rows.** File: `insert_picker.rs`.
- **Row kinds.** `Item` gains `kind: ItemKind`:
  - `Shape {master}`: today's rows.
  - `Next {type_id, relationship}`.
  - `Connect {from, to, relationship, legal}`.
  - `Pattern {id}`.
- **Row order:**
  1. With one shape selected, `Next` rows from `vizcraft_engine::suggest::next(doc, id)`, labelled "<relationship label> to <type label>" in the group "From <shape text>".
  2. With exactly two shapes selected (in selection order), `Connect` rows from `suggest::connect`. Illegal choices are dimmed with "not allowed" and still run, because rules lint and never block.
  3. Shape rows.
  4. `Pattern` rows from `panes::patterns::groups(app)` in the group "Pattern".

  Filtering and `MAX_ROWS` are unchanged.
- **What Enter or a click runs.** `Next` runs `insert.next {id, direction: flow, type, relationship}`, then naming starts. `Connect` runs `insert.connect {from, to, relationship}`. `Pattern` runs `pattern.insert {pattern, x, y}` with defaults, and the Patterns pane changes it afterwards. The hint text becomes "Insert a shape, relationship or pattern".
- **Row icons.** Relationship rows draw a short line with the connector kind's end arrow.
- **Opening with `/`.** The picker opens at the pointer when it is over the canvas, else at `canvas::insert_point`. The `/` that opened it must not land in the query: drop that frame's `Event::Text("/")`.
- **Control channel.** `ui.insertPicker` keeps `items` (ids) and adds `rows: [{id, kind, label, group}]`.

**3. Connector label editing.** New file `canvas/interact/labels.rs`, with hunks in `interact/mod.rs` and `edit_text.rs`.
- **Hit test.** `labels::label_at(app, ui, vp, pos) -> Option<(connector id, Part::{Main, Start, End})>` measures each label as `canvas/draw/connectors.rs` lays it out (`label_layout` around `g.label_pos`, and `arrows::end_label_anchor` for the end labels). A double-click checks this before `dg::hit`, so a wide label off a thin line still edits.
- **Empty end label.** A double-click on the route within its first or last 15 percent, on a connector whose relationship type declares `end_labels`, edits that (empty) end label.
- **Editing state.** `TextEditing` gains `label: Option<End>` (start or end). `placement` centres the editor on the end-label anchor. `commit_editing` runs `connector.setEndLabels {ids: [id], start|end: text}`. Bind step 9 then writes the text back to the role and multiplicity properties (`split_label`): "items 1..*" sets role and multiplicity; "1..*" sets the multiplicity only.

**4. Compartment edits that stick.** Hunks in `edit_text.rs`.
- **The bug.** Today a double-click on a `rowsFrom` compartment (UML `attrs`, `ops`, `literals`) or on an owned-table compartment (ER `keys`, `attrs`) commits `compartment.set`. The next sync overwrites it from the model, so the edit is lost.
- **`rowsFrom` bands** (`cat.compartments_in(type, variant)` gives the declaration): the editor shows the element's raw property text and commits `element.setProperty {id, key: rows_from, value}`. Visibility hidden by the `uml.nameOnly` or `memberVisibility: hidden` variants is therefore not lost.
- **Owned-table bands:** a double-click edits the cell under the pointer. The row comes from `dg::hit::band_of(..).row`, mapped to the attribute id through the new `sheet_pass::table_row_ids`; the column comes from the compartment's `columns` widths.
  - A `name` cell commits `element.rename`.
  - Other text cells commit `element.setProperty`.
  - Bool cells (`pk`, `fk`) toggle on the double-click.

  Each is one command, so one undo step.
- **Paragraph bands filled from properties** (`uml.State` behaviours): the double-click opens the Inspector's Properties section instead of an editor that would be overwritten.

**5. Steps and key.** New files `ribbon/notation/key.rs` and `ribbon/notation/steps.rs`, `canvas/interact/steps.rs` and `canvas/draw/steps.rs`.
- **Notation-tab groups:**
  - **Key:** Insert Key, Refresh Key, Remove Key (`key.insert`, `key.refresh`, `key.remove`).
  - **Steps:** the Steps tool toggle (`ui.tool {tool: "steps"}`), Renumber (`connector.renumberSteps`) and Clear Step (`connector.setStep {id: selected connector, step: null}`).
- **The Steps tool.** `Tool::Steps` in `lib.rs`, with name and parse arms "steps".
  - A click on a connector runs `connector.setStep {id, step: highest on page + 1}`.
  - A Shift-click clears its step.
  - Escape returns to the pointer (one arm in `canvas/interact/keys.rs`).
  - The status bar says "Step n: click a connector".
- **Badges on the canvas.** `canvas/draw/steps.rs` draws each badge from `vizcraft_diagram::step_badge::badge(c, &g.polyline)` the way the SVG export does: a filled accent circle with the number from `Tokens`. One call at the end of `draw::connectors::connector`.
- **Include in key.** The Inspector shows an "Include in key" checkbox when `key.get` reports a key on the page. It adds or removes the element's type id (or the connector's kind id) in `exclude` and runs `key.insert {exclude}`, which rebuilds the key in place as one undo step. Key freshness stays explicit; there is no auto-refresh.

**6. Model Tree relationship rows.** File: `panes/model_tree.rs`.
- **Rows.** A new `Kind::Relationship {rel, other, outgoing, label}` row appears under an open element, after its owned children: "-> Composition: LineItem" or "<- Association: Customer". An element with relationships is expandable. The row key is `rel:<element>:<relationship>`.
- **Clicks.** A click selects the relationship's connectors (`select_runs` with the relationship id). The context menu has Change Type (`relationship.retype`, with the types from `suggest::connect` for the drawn pair) and Delete from Model (`model.delete {ids: [rel]}`).
- **Context mode** shows the selected element's relationships expanded.
- **Control channel.** `model_tree::inspect` adds `relationships: [{element, id, direction}]` for the visible rows.

**7. Inspector: ends, members, columns.** New sibling modules `panes/inspector/{relationship,members,columns}.rs`, declared with `mod` lines in `inspector.rs` (no rename of `inspector.rs`).
- **Relationship section** (a connector with a relationship selected), fed by the extended `inspector.get` (engine item 2):
  - Type: a combo that runs `relationship.retype`.
  - Name: runs `connector.setText`.
  - Ends: two columns headed by the source and target element names, each holding its end properties through the existing `prop_editor`.
  - Then the other properties, then "Include in key".
  - **Writes:** `relationship.setProperty`. ER cardinality uses the same path; `er.setCardinality` is its batch twin for agents.
  - **Multiplicity keys** (the key ends in `Multiplicity`) show the reason from `uml_text::parse_multiplicity` in red under the field, but still write.
  - **Fix ends.** When `session.issues` holds an `endMarkerMatchesProperty` issue naming this relationship or connector, a "Fix ends" button runs its fix inside `edit.batch {label}`, as `dock/problems.rs` does.
- **Members section** (an element whose type declares `rowsFrom` compartments): one list per compartment (Attributes, Operations, Literals).
  - Each row has a visibility combo (none, `+`, `-`, `#`, `~`), a text field holding `format_member` without visibility, up, down and delete.
  - An Add row closes the list.
  - Every change runs one `uml.*Member` command (engine item 1). Problems are shown inline.
- **Columns section** (an element whose type declares an owned table query): a grid of Name, Type, PK, FK, Null, Unique and delete, in drawing order (`table_row_ids` over each owned compartment).
  - Edits run `element.rename` or `element.setProperty` on the attribute; delete runs `model.delete`.
  - **Add column:** `er.addColumn {entity, name, dataType, pk}` for an `er.Entity` chain, else `element.create {type: query.types[0], owner, name}`.
- **Shared plumbing.** `Extra::gather` gains cached `relationship` (from `inspector.get`) and `key` (from `key.get`) entries, cached per revision like the existing reads. `inspect_fields` adds `relationship`, `members` and `columns` for the control channel.

**8. Notation-aware Layout.** File: `ribbon/design/layout.rs`.
- **Re-Layout control.** Re-Layout becomes a `Custom` split with the label "Re-Layout" kept, because `design_tab_relayout_menu_and_route_button_run_their_commands` clicks it by label.
  - The main click runs the first notation choice, else layered top to bottom.
  - The menu shows a section titled with the viewpoint's label, built from `notation_layout::layout_choices`: the distinct `TemplateLayout`s of the viewpoint's templates, with `roles` dropped so the primitives use their page defaults. Examples are "Layered, Left to Right (State machine)", "Nested containers", "Entity-relationship" and "Pipeline".
  - Then comes the existing generic list, unchanged.
  - Entries run `layout.full {algorithm, direction}` or `layout.primitive {primitive, direction?}`.
- **Insert Direction** is a small menu in the group: Auto (shows what it resolves to), Right, Down, Left, Up. It runs `ui.insertDirection`.

## Engine additions (minimal)

   - Caps are `uml_text::MAX_ROW` and `compartment::MAX_ROWS`.
   - Tests cover each command on `template.new uml.classDiagram`, refusal on a flowchart element, a bad multiplicity reported, and undo.
   - Add junk rows to `hostile_params_never_panic`.
   - Add `uml.*` (`cmd/uml.rs`) to the prefix list in docs/architecture.md.
2. **`inspector.get` on a connector or relationship id** (`cmd/inspector.rs`).

   - A connector with no relationship returns empty lists, not an error.
   - Tests: a UML association (four end rows plus navigability), an ER relationship (cardinalities on their ends), and a free connector.
3. **`vizcraft_notation::sheet_pass::table_row_ids(doc, cat, owner, q) -> Vec<String>`.** Refactor `rows_of` to carry ids. Test: the ids line up with `table_rows` for `er.schema`.

## Risks and open questions

- **egui Tab focus.** egui may move keyboard focus on Tab in `begin_pass`, before `logic` consumes the key. If a kittest shows a ribbon button gaining focus, filter Tab in `CraftApp::raw_input_hook` while canvas keys are allowed (use the previous frame's state), and say so in the report.
- **Keyboard ownership on sequence pages.** `b6-sequence-ui` owns "keyboard flow" there. This branch makes Tab and Enter no-ops on `Page.sequence` pages through `notation_layout::sequence_page`. The two branches must not both bind Tab.
- **Unassigned ER canvas drawing.** The canvas does not draw ER `Compound::Double`, `Connector.halves` or `label_frame` (Chen, Barker), and the Arrows menu lacks "Double bar" and "Dot". These are in neither this scope nor `b6-polish`'s list. The orchestrator should assign them.
- **Two undo steps for Tab plus a name.** Tab with a typed name is two undo steps (insert, then name). Merging them would need an engine "amend last step" mechanism; this is a follow-up if the user wants one step.
- **Fragile row mapping.** Owned-table cell mapping depends on `table_row_ids` matching `rows_of` order. The test pins it.
- **`uml.*` is a new prefix.** If the orchestrator prefers `element.addRow`-style generic ids, the four commands rename with no UI change.
- **UML transition labels.** `connector.setText` on a `uml.Transition` renames the relationship. Whether its trigger, guard and effect label should parse back into those properties is out of scope; note it if seen.
