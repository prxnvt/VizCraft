## Scope

### 1. ER tables: clipped types and two header rows

- **Clipping, cause.** `fit()` in `crates/formats/src/svg/compartments.rs:115` cuts each cell at a flat 0.55 em per character. The IE Type column is 90 wide; minus `2 * PAD_X` that leaves 78, which allows floor(78 / 6.6) = 11 characters. `varchar(255)` has 12, so it is cut to `varchar(255` with no mark that anything was cut. The canvas has a copy of the same `fit` in `crates/ui-egui/src/canvas/draw/text.rs` (added by b6e-frontend).
- **Clipping, fix.**
  - Add `pub fn fit_cell(text: &str, width: f64, font_size: f64) -> String` to `crates/diagram/src/compartment.rs`.
    - Estimate widths with per-character classes for Inter instead of a flat 0.55: narrow (`i l j t f r ( ) [ ] . , : ; ' | !` and space) about 0.3 em, digits about 0.6, upper case about 0.68, `m w M W` about 0.9, everything else 0.55.
    - Text that is cut ends in `…` (U+2026), and the result including the ellipsis stays within `width`.
  - Use `fit_cell` in `table_svg` and in the canvas `table_text`, and delete both local `fit` functions.
  - On the canvas, also clip each cell with `painter.with_clip_rect` so real glyph widths never spill over.
- **Two header rows, cause.**
  - `compartment::layout` (lines 414-415) gives every list with columns a header row, and `natural_height` (line 365) adds a line for it.
  - `crates/notation/packs/er.json` declares two query compartments per entity, `keys` and `attrs`, and both have titles: IE `attrs` headers are `["", "Column", "Type"]` (on `er.Entity` and `er.WeakEntity`), and the Barker variant `attrs` headers are `["", "Attribute"]` (around lines 1375-1490).
- **Two header rows, fix.**
  - Add `Compartment::has_header(&self) -> bool`: a list with columns where at least one title is not blank. `layout` and `natural_height` both use it, so a table whose titles are all blank draws columns with no header row.
  - In SVG and canvas, choose the table path on `!b.columns.is_empty()` instead of `b.header.is_some()`. The column rules run the full band, `b.rect.y0` to `b.rect.y1`; today they start at `h.y0`, which leaves the 4-unit gap visible in er.schema.png.
  - Canvas hunks: `canvas/draw/shapes.rs` (the separator loop, `let Some(h) = b.header else { continue }`) and `canvas/draw/text.rs` (`CompartmentKind::List if band.header.is_some()`).
  - In er.json, make the `attrs` headers all blank, for IE (both types) and for Barker. Each table then has one header row, from `keys`.

### 2. Step badges sitting on line labels (cloud topology)

- **Cause.** `step_badge::badge` (`crates/diagram/src/step_badge.rs`) always puts the badge at `ALONG = 0.25` of the route and ignores the label. The label box is centred at `route.rs` `label_pos` (0.5 along) and sized in `svg.rs` (`CHAR_WIDTH 0.6`, around line 438). On a short route the quarter point falls inside the label: gateway to balancer "route", and "query", in cloud.topology.png.
- **Second gap.** The canvas never draws badges. Nothing in ui-egui calls `step_badge`, although the module doc says the canvas does.
- **Fix, engine.**
  - Add `pub fn label_size(text: &str, st: &Style) -> (f64, f64)` to `crates/diagram/src/connector_look.rs`, with the same formula `svg.rs` uses.
  - Do not edit the label block in `svg.rs`; `b6-sequence-ui` owns that hunk. Instead, add a test asserting the SVG label rect width equals `label_size`.
  - In `badge`, when the connector has text, work out the label's half extent along the route at the midpoint. Clamp the badge distance to `[radius + gap, L/2 - extent - radius - gap]`.
  - When that interval is empty, put the badge at `radius + gap` along the route, offset sideways by `radius + line width + gap`: above a horizontal run, left of a vertical one.
- **Fix, canvas.** Draw the badge in `crates/ui-egui/src/canvas/draw/connectors.rs` after `end_labels`, as the SVG does: a filled circle in the line colour, a white outline, and a bold white number at `radius * 1.1`.
- **Ownership.** `b6-ux` owns the Steps tool and key UI; this branch owns drawing the badge.

### 3. Actor, User and Internet labels drawn on their figures

- **Cause.**
  - Path glyphs `cloud.user` and `cloud.internet` (`cloud.json` around 397 and 416) and `uml.actor` (`uml.json` around 1995) have no text placement.
  - `Master::instantiate` and `redraw` (`crates/stencils/src/lib.rs:223`) leave `text_block` as `None`, so `Shape::text_rect` is the whole frame and the name is centred on the figure.
  - The sequence actor lifeline already places its name below the figure (`sequence.rs:900`); leave it alone.
- **Fix.**
  - Add `TextPlace { Inside, Below }` to `crates/diagram/src/model.rs`, stored as `Shape.text_place` (serde `textPlace`, default `inside`, skipped when it is the default).
  - `Shape::text_rect` order: an explicit `text_block` wins; otherwise `Below` gives a rect centred under the frame, starting 2 units below it, `max(w, 160)` wide and two line heights tall.
  - `board::drawing_bounds` includes that rect when the text is not empty, so infinite-board exports do not clip it.
  - Canvas drawing, the text editor (`canvas/interact/text_block.rs`) and the SVG export all read `text_rect`, so they follow without further changes.
  - Pack field: `Glyph.text_place` (`"textPlace": "below"`) in `notation/src/schema.rs`. The loader check in `loader.rs` accepts `inside`, `below` or empty. `Master.text_place` is set in `master_from_glyph`, applied in `redraw`, and the `Master { .. }` literal in the stencils test is updated.
  - Set `"textPlace": "below"` on the three glyphs.
- **User choice.** `text.setBlock` gains `position?: "inside"|"below"`. Its params string and its error text ("give at least one of …") are updated to match.

### 4. Italics missing in PNG and PDF

- **Cause.**
  - `png::fonts()` loads only Inter Regular, Medium and SemiBold. usvg 0.47 does not synthesise oblique (checked: there is no skew path in `usvg-0.47.0/src/text`), so `font-style="italic"` falls back to upright. PDF goes through the same `parse_svg`.
  - Related: `Compartment::text_style` (`compartment.rs:261`) inherits the shape's italic. The abstract class `Party` therefore italicises `+name: String` as well (`uml.classDiagram.svg` line 8). UML italicises only the name.
- **Fix.**
  - Add `assets/fonts/Inter-Italic.ttf`, from the same Inter release as the bundled faces (github.com/rsms/inter, OFL-1.1), with its ATTRIBUTION.md row in the same commit, and load it in `png::fonts()`.
  - In `text_style`, reset `italic` to `false` next to the existing bullets and case reset. Rows "draw as typed"; per-row italic for abstract operations is the b6-uml row-markup follow-up, not this branch.

### 5. `dfd.threat` clutter

- **Labels.** If the labels of an opposite pair still overlap after (a) to (c), report it. Do not add label placement here: `svg.rs`, `route.rs` and `label_pos` are `b6-sequence-ui`'s territory.

## Risks and open questions

- **Font size.** Inter-Italic adds about 410 KB to the native and wasm binaries. A bold italic falls back to the regular italic face. If the user does not want the size, the fallback is no italics in PNG and PDF, recorded as a known limitation.
- **Width estimate.** Character classes are still an estimate. Cells could be measured with the real font in formats, but the canvas and layout would then disagree; the shared estimate plus a canvas clip is the compromise.
- **Text below a figure.** It is not in the layout's node size, so a neighbour placed directly below can touch the label. Widening layout sizes is a separate change.
- **Edge dedupe.** The nested dedupe changes any nested layout with two-way pairs. Check the cloud and network template goldens' diffs, not just dfd.
- **Shared file with `b6-sequence-ui`.** `canvas/draw/connectors.rs` is edited by both branches. Merge `b6-polish` after `b6-sequence-ui`, or keep this hunk to the badge call.
- **Type label.** Should `uml.Decision`'s type label become "Decision Node" (the UML 2.5.1 metaclass is DecisionNode)? That would also remove the label clash in the Model Tree. This is the user's call; this branch keeps "Decision".
