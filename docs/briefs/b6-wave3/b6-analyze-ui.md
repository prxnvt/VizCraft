## Scope

**Analysis options (`dock/analysis.rs`, `AnalysisState` in `DockState`, not persisted).** Every option is the user's choice, with a default:
- `depth`: `None` (All, the default) or 1..=1024
- `types`: the relationship types to follow. Empty (the default) follows every link.
- `containment`: default false
- `dim`: dims items outside the result. Default true.
- `live`: re-runs a stale graph analysis on the next frame. Default false; `model.diff` is never re-run live because it reads a file.
- `diff_filter`: added, removed, changed or all. Default all.

The tab also keeps:
- `last: Option<(String, Value)>`: the command and resolved params of the last successful run, for Re-run.
- `selected: Option<String>`: the selected row id.
- `sort: Option<(usize, bool)>`: the metrics column and direction.

New UI command `ui.analysis {depth?: n|"all", types?: [id], containment?, dim?, live?, filter?, row?: id, goto?: bool}` sets the options, opens the dock on Analysis, and replies with `inspect(app)`. Junk is ignored field by field, and depth is clamped.

**Running.** `dock::ui_command` routes `analyze.dependencies|cycles|unreachable|spof|metrics|path`, `analyze.clear` and `model.diff` to `analysis::on_run(app, id, p)`, from every origin. `on_run` does the following:
1. Runs `app.session.run(id, p)`, then `app.after_command()` (private in `lib.rs`, visible to descendants), and puts errors in the status bar, the way `app.run` does.
2. On success, stores `last`. For `analyze.dependencies` called without `id`, it fills `id` from `result.levels[0][0]`, so Re-run does not follow a later selection.
3. Clears `selected`.
4. Opens the dock on Analysis when `session.origin()` is `Ui`, as `problems::on_run` does for Problems.

`analyze.clear` also drops `last`. `refresh(app)` is called at the top of `dock::show`, before the `open` check, so it runs every frame. It re-runs `last` when `live` is on, the result is stale (`rev != session.rev()`) and the kind is not `diff`.

**Ribbon, Model tab** (`ribbon/model/mod.rs`: `groups! { model, analyze, compare }`).

`analyze.rs` is the Analyze group. Every button's `ParamsFn` adds the current `depth`, `types` and `containment`, and omits them when they are at their defaults.
- Stack 1: `Button` "Upstream", "Downstream" and "Both" on `analyze.dependencies {direction}`. With nothing selected, the engine's error reaches the status bar.
- Stack 2:
  - a `Row` holding a `Label` "Depth" and a `Combo { id: "ui.analysis", param: "depth", items: 1, 2, 3, 5, 10, All }`;
  - `Button` "Path" on `analyze.path {from, to}`, taking the first two selected elements in selection order (`selected_elements` from `model.rs`, made `pub(super)`);
  - `Small` `analyze.metrics`.
- Stack 3: `Small` `analyze.cycles`, `analyze.unreachable` and `analyze.spof`.
- `Custom(follow_menu)`: a "Follow" menu with one checkable row per relationship type used in `doc.model.relationships`, plus "All links" and "Include containment". It sets options through `ui.analysis`.

`compare.rs` is the Compare group:
- a big `Split` on `model.diff` (icon `compare`) with the menu "With Saved File" (`model.diff {against: "saved"}`) and "With File..." (`ui.compareFile`);
- a Stack with `Small analyze.select`, `Button` "Clear Highlights" (`analyze.clear`, icon `eraser`), and `Button` "Results" (`ui.dock {tab: "analysis"}`, checked while the dock is open on Analysis).

Git HEAD is not offered: the engine refuses it, so it is listed as a follow-up.

New UI command `ui.compareFile {}`: `services.pick_open("document")`, then `model.diff {path}`. With no picker (web, tests) it returns `{picked: false}` and leaves everything unchanged, as `pictures::ui_command` does. `apps/vizcraft` needs no change, because unknown purposes already get the VizCraft document filter.

**Canvas highlights (new `canvas/draw/highlights.rs`).**
- `pub fn targets(session, page) -> Vec<Target {item, mark, chip: Option<String>}>` is a pure function. It is used by both the drawing and `ui.inspect`:
  - shapes whose `element`, and connectors whose `relationship`, has an entry in `analysis.marks`;
  - ids the model no longer has are skipped (`model.contains_id`);
  - `chip` is the level number for `dependencies` (from `detail.levels`), the step index for `path`, and otherwise the short mark name ("Cycle", "Cut", "New", "Changed", "Unreachable"). Colour is never the only signal.
- `pub fn draw(painter, vp, session, page, opts, t)`, over visible items only:
  - each marked shape gets a rounded halo around its bounds, inflated by 4 px, with a 2.5 px stroke (Focus 3.5 px) and a 12 % tint fill;
  - Unreachable uses a dashed stroke;
  - each marked connector gets a 6 px band at 45 % along `route_polyline`, as `nets::highlight` draws it;
  - the chip is a small rounded label at the halo's top-left, drawn only when zoom ≥ 0.4;
  - with `dim` and a non-diff result, unmarked visible shapes and connectors get a 55 % `t.page` wash;
  - a stale result draws at 40 % alpha;
  - for `diff`: ghosts from `detail.ghosts` whose `page` is the active page's id are drawn as dashed `t.red` outlines or polylines, with the name struck through.
- Colours come only from `theme::Tokens`, through `mark_color(t, Mark)`:

  | Mark | Token |
  |---|---|
  | Focus | `accent` |
  | Upstream | `blue` |
  | Downstream | `amber` |
  | Cycle | `red` |
  | Unreachable | `violet` |
  | Cut | `red` |
  | Path | `accent` |
  | Added | `green` |
  | Removed | `red` |
  | Changed | `amber` |

- It is called in `canvas/mod.rs::paint` right after the net highlight and before `data_graphics::marks`, so selection handles stay on top.
- `status_items` adds "Analysis: <summary>" when a result exists, plus " (out of date)" when it is stale.

**Analysis dock tab (`DockTab::Analysis`, name `analysis`, title "Analysis", between Nets and Generate).**
- With no result, a hint: "Run an analysis from the Model tab."
- Header row:
  - the kind's label (from `vizcraft_analysis::analyses()`, or "Compare" for `diff`) and the `summary`;
  - an "Out of date" badge with a Re-run button when stale (Re-run is enabled only when `last` is set);
  - a "Truncated at 10,000" note when `truncated`;
  - Select (`analyze.select`), Clear (`analyze.clear`), Dim and Live checkboxes;
  - a legend of the marks present.
- Body by kind, read from `Session.analysis` directly. Each row has Name (from `model.element(..).name`, else the id), Type and a "Why" column:

  | Kind | Rows | Why column |
  |---|---|---|
  | `dependencies` | elements, then relationships | "Level n downstream" or "upstream" |
  | `cycles` | one collapsing header per group ("Cycle k, n elements") | Go to selects the group's items |
  | `unreachable` | elements, plus a "Roots:" line from `detail.roots` | |
  | `spof` | Cut points and Bridges sections | |
  | `path` | ordered steps (element, relationship, element...) | |
  | `metrics` | `table` with headers Fan-in, Fan-out, Layer and Containment depth; a header click sorts locally (UI-only, no re-run); totals and critical path below | |
  | `diff` | Added, Removed and Changed rows from `detail.elements` and `detail.relationships`, with the `diff_filter` chips | Changed rows list `field: before → after` |
  | unknown kinds (later packs) | generic lists of elements and relationships with their marks, plus `table` when present | |

- Go to (row click or Enter on the focused row):
  1. find the item's drawing on the active page, else on the first page `views_of` lists, and switch with `page.setActive`;
  2. `edit.select` the drawing items;
  3. `view.pan {x, y}` to the item's centre when it is off screen (pan is the world point at the canvas centre; confirm against `canvas::initial_pan`).

  A Removed row goes to its ghost's page when the current document has it; otherwise the status bar says the compared file drew it on a page this document lacks.
- `dock::inspect` rows: the number of rows the tab lists.

**`ui.inspect`.** It gains a top-level `analysis` entry:

```
{kind, summary, count, rev, stale, truncated, highlighted, ghosts, selected, options, last}
```

Here `highlighted` is `targets(..).len()` on the active page and `ghosts` counts the ghosts drawn there.

**Keyboard and undo.** No new shortcuts. Every action is in the command palette through the registry and `UI_COMMANDS`. None of this branch's actions makes an undo step: analyses, Select, Go to (`page.setActive` is "not an undo step"), Clear and Compare. ## Engine additions (only in `crates/engine/src/cmd/analyze.rs`)

1. **`model.diff` ghosts.** After `load_bytes`, one pass over `before.pages` collects every shape whose `element`, and every connector whose `relationship`, is in the removed sets. Each becomes:

   ```
   {"id", "page": page id, "pageName", "item", "kind": "shape"|"connector", "name", "rect": [x, y, w, h]?, "points": [[x, y]...]?}
   ```

   `rect` comes from `Shape::bounds()`; `points` comes from `vizcraft_diagram::route_polyline`, capped at 256 points. The total is capped at `MAX_RESULT_IDS`. The list is stored as `detail.ghosts` on the stored result and returned as `ghosts` in the `model.diff` reply. The params doc string gains `"ghosts"`.

   Test `diff_draws_removed_items_as_ghosts_from_the_compared_file`: save `flow()`, `model.delete {ids: ["ok"]}`, then `model.diff`. The ghosts hold the shape of `ok` with its saved rect and connector `f2` with at least 2 points, on the saved page id.
2. **`result_json` key collision.** For `diff`, the merged `detail` keys `elements`, `relationships` and `truncated` collide with the result's own, so `analyze.result` loses the per-field changes. When any detail key already exists, keep the whole detail under `"detail"` as well.

   Test: `analyze.result` after a rename diff has `detail.elements.changed[0].id == "do"`.

## Risks and open questions

- **Compare page versus overlay.** The research mentions a "Compare page". This brief draws the diff as an overlay on the real pages, so it adds no undo step, does not dirty the document, and leaves no generated page behind. If the user wants a printable compare page, a later `model.diffPage` can generate one from the same ghosts.
- **Git HEAD.** It is still refused by the engine (wasm, and it needs a `Services` hook), so the menu leaves it out rather than showing a disabled entry.
- **Shared token names.** `Tokens` gains `blue`, `amber` and `violet`. If another wave 3 branch adds similar tokens, the integration merge should keep one set.
- **Direction wording.** For "depends on" relationships, callers are upstream (wave 1 risk). The tooltips say "follows links from source to target" rather than naming dependency semantics. A pack-declared dependency direction is still a follow-up.
- **Dependencies with nothing selected.** The click errors into the status bar, because ribbon controls cannot be disabled per-params. A `Control::Button` enable hook would be a ribbon-wide change and is left out.
- **Live re-run cost.** It runs on every edit while `live` is on, and the analyses are linear. It is off by default and never applies to `diff`.
- **Ghost geometry.** Ghosts use axis-aligned bounds, so rotation is ignored. Removed items on pages the current document lacks show only in the dock.
- **Pack notation tabs.** The notation tabs may later want their own Analyze group (research §Ribbon). That is out of scope here; the ribbon module is reusable.
