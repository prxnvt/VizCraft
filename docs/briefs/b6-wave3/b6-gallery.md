# `b6-gallery`: template gallery, project standards at creation, engineering workspace preset (Block 6 wave 3 frontend)

Opus, medium effort. Port 8061. Worktree `.claude/worktrees/b6-gallery`, branch `b6-gallery`, starting from the integration branch `claude/engineering-diagramming-standards-305d6b` after `b6e-frontend` has merged. Use `export CARGO_TARGET_DIR=target-b6-gallery CARGO_INCREMENTAL=0` for every cargo command. Commit prefix `B6:`. The control channel is on 8061 only. Screenshots go under `/private/tmp/claude-501/b6-gallery/`. Launch the GUI on the secondary monitor with `VIZCRAFT_NO_PREFS=1 cargo run --release -p vizcraft -- --control 8061 --window-pos -2500,100`, quit it through `app.quit` (Don't Save) as soon as you have looked, and check with `pgrep -fl vizcraft`. Prefer the headless `ui_shot` example and kittest. Read AGENTS.md first. Then read these `docs/cascade-plan.md` sections: "How Blocks 6 and 6E run", "Block 6 and 6E wave 1 contracts" and "Block 6 wave 2". Also read `docs/research/swe-diagramming-ux.md` ("Workspace changes": New page, Engineering workspace preset, Ribbon), `docs/briefs/b6-wave1/b6-templates.md` and `docs/briefs/b6e-frontend/report.md`.

**Goal.** Replace the File page's New screen with a template gallery over `template.list`. It has:
- search, audience chips, a Recent row, and cards grouped by pack, each with a preview drawn from the template;
- a details panel where the person picks the notation variant and sheet;
- a standards bar (symbol family: IEC by default, ANSI, JIC and the rest; sheet: ISO A3 landscape by default, every ISO and ASME/ANSI size) that `template.new` writes into `Document.standards`.

The same gallery adds a page from a template (`template.addPage`). An engineering workspace preset (`ui.preset`) sets the workspace defaults and switches the Home tab to an engineering arrangement. The office preset stays exactly as today. Path and builder glyphs get real outlines wherever the UI still draws a generic box. Every standard is a choice with a default: nothing is hardcoded, and the person can always change it.

## Scope

**Gallery (new `crates/ui-egui/src/gallery.rs`, drawn by `backstage.rs`).**
- **Entry points.**
  - The File page's New row: `backstage.rs` swaps `set_new_page`/`new_from_notation` for the gallery, and the Escape and back handling stay as they are.
  - `ui.gallery`.
  - A File menu row "New from Template..." placed after "New".
- **Transient state.** `pub gallery: gallery::Gallery` on `CraftApp`: open, mode (`new`|`page`), query, audience, selected id, dirty-notice flag. It replaces the `backstage_new` temp key.
- **Layout, top to bottom.**
  - The title, which reads "New" or "Add Page".
  - The search field (`TextEdit`, accessible label "Search templates", focused on open).
  - Audience chips: "All", then each audience value in first-seen order, title-cased.
  - The standards bar.
  - In `new` mode while `UiState.preset` is empty, a Workspace row (see the preset section).
  - A Recent row, then one section per pack with `packName` as the heading.
  - Cards in a wrapping grid. Each card is about 220 by 170 points and holds the preview, the label, a one-line description clipped like `card()` does, and small chips for `codeForms` and for "Key" and "Title block" when set.
- **Blank cards.** Packs with viewpoints but no templates (today `sheet`) keep a "Blank <Pack> page" card that runs `file.new` and then `model.setViewpoint`, as `new_from_notation` does now. "Blank drawing" stays first and is `basic.blank` through `template.new`.
- **The list.** It comes from a new engine helper, `template::listing(audience, pack, query)` (see Engine additions). Calling it directly means typing in the search box records nothing into a macro. It is cached in the gallery by `(catalog address, query, audience)`, with the catalog address taken as `profile_cache` does, so `notation.load` refreshes it.
- **Details panel.** It sits on the right while a card is selected and holds:
  - a larger preview, the description, keywords and code forms;
  - a Notation combo, shown only when the pack has variants. It lists `variants` from the listing plus "Default drawing". It is pre-set to what the engine would choose (`template::resolved` with the bar's standards). The UI sends `variant` only if the person changed it.
  - a Sheet combo, shown only when the template has a `sheet`. It lists "Project sheet (<label>)", every preset, and "No sheet" (`sheet: ""`).
  - a Create button (default on Enter).
- **Choosing.** A single click on a card selects it; a double-click creates.
- **Create in `new` mode.** It runs `template.new {template, standards: {symbols, sheet}, variant?, sheet?}`. On success:
  - push the id to `UiState.recent_templates`;
  - apply the Workspace choice if one is pending;
  - close the File page;
  - run `ui.pane.shapeData {value: true}` to open the Inspector;
  - the page fits through the `fits_after` hunk.
- **Unsaved changes.** If `session.dirty` is set, Create first shows an inline notice in the details panel: "The drawing has unsaved changes; creating replaces it", with the buttons Save First (`file.save`, then create), Replace and Cancel. Nothing is lost silently.
- **Errors.** On error, the status bar shows the engine's message and the gallery stays open. The document is unchanged, because the engine makes a dry run first.
- **Create in `page` mode.** It is opened from Insert > Pages and from the page-tab context menu. It runs `template.addPage {template, variant?, sheet?}`, which is one undo step. In this mode the standards bar edits the document's standards through `template.standards {symbols|sheet}`, one undo step per change, so the engine's defaults (`doc.standards`) are what the person sees.
- **Keyboard.**
  - Typing filters.
  - Up and Down move the selection by row; Left and Right move it by card when the search text is empty.
  - Enter creates the selected card, or the first card shown when none is selected.
  - Escape clears a non-empty search first, then closes, as today.
- **`ui.gallery` (in `UI_COMMANDS`).** Params: `{open?: bool, mode?: "new"|"page", query?, audience? ("" = All), select?: template id, symbols?, sheet?, create?: bool}`. Result: `{open, mode, query, audience, selected, shown: [id], pending, symbols, sheet}`.
  - `create: true` runs exactly the Create path. If the document is dirty, it returns an error naming the notice instead of replacing anything.
  - A junk mode, an unknown template or a bad sheet is an `Err`, and the state is left alone.

**Standards bar.**
- **Symbols combo.** Choices are `SYMBOL_CHOICES`: IEC first, then ANSI, JIC, IEEE, ISA, ISO, shown upper-case with a tooltip.
- **Sheet combo.** Choices come from `sheet.presets`, read once per gallery open with `session.run` as `ribbon/sheet/sheet.rs` does. ISO sizes come first, then ASME. Each row is labelled "<standard label> <size name> <orientation>", and there is a Landscape/Portrait pair.
- **Defaults.** In `new` mode the defaults come from `UiState.new_standards`, the last choice, kept in preferences and sanitized in `apply_prefs`. When that is empty they are IEC and `iso.a3.landscape`, from `vizcraft_diagram::standards::{DEFAULT_SYMBOLS, DEFAULT_SHEET}`. Changing either one updates the prefs and invalidates the details preview.

**Previews (new `crates/ui-egui/src/gallery_previews.rs`).**
- **Pipeline.**
  1. `(variant, sheet) = template::resolved(id, &choices, Some(&bar_standards))`.
  2. `doc = template::build(t, &Choices{variant: Some(variant), sheet: Some(sheet)})`.
  3. `vizcraft_engine::io::export_page_bytes("p.png", None, &doc, doc.active_index(), scale)`, with `scale` fitted so the longest side is about 2x the card's preview width in physical pixels. The renderer clamps it to its 0.25 minimum.
  4. Decode with `image::load_from_memory_with_format(.., Png)`, shrink with `image::imageops::thumbnail`, and load into a `TextureHandle`.

  No new dependency is needed: `image` with `png` is already a ui-egui dependency, and the export goes through the engine.
- **Cache.** It lives in egui memory, like `canvas/draw/pictures.rs`, and is keyed by `(template id, variant, sheet, catalog address)`. It is capped at 64 entries, dropping the least recently drawn.
- **Budget.** At most one build per frame while the gallery is visible, with a repaint request while any card is pending. A pending card shows a drawn placeholder (the pack name on the `t.panel` fill). A failed build is cached as failed and shows "No preview", never a panic.
- **Inspection.** `pending` is reported in `ui.gallery` and in `ui.inspect`.

**Recent.** `UiState.recent_templates`, newest first, at most 8, deduplicated. `CraftApp::run` pushes the id after a successful `template.new` or `template.addPage` from any origin. The row skips ids the catalog no longer has and has a "Clear" link (`ui.gallery {clearRecent: true}`).

**Engineering workspace preset (new `crates/ui-egui/src/preset.rs`).**
- **`ui.preset {name?: "engineering"|"office"}`** returns `{preset, applied: [setting]}`. With no name it reads the preset; an unknown name is an `Err`. Setting a preset stores `UiState.preset` and applies its defaults once; each setting stays individually changeable afterwards.
  - Engineering: `aids.rulers = false`; Model Tree (`navigation`) opened, uncollapsed and moved to the top of the left side above Shapes; Inspector (`shapeData`) open on the right; ribbon tab Home.
  - Office: rulers on, and the left pane order and collapse of `PaneLayout::default()`.
  - `panes.sanitize()` runs after either.
- **Unset preset.** An empty `UiState.preset` draws the office look, so existing installs and every existing snapshot are unchanged. While it is empty, the New gallery shows a Workspace row (Engineering, Office). It is preselected from the audience chip: `software`, `engineering` and `industrial` give Engineering, anything else Office. The first Create runs `ui.preset` with it, and the status bar says "Engineering workspace on; View > Workspace switches back".
- **Switching later.** View > Appearance gets a Workspace menu with two checked rows that run `ui.preset`.

**Home tab per preset.**
- `ribbon/home/mod.rs` gets `pub(super) fn tab(app: &CraftApp) -> Tab`. It returns today's `groups()` for office or unset, and `engineering_groups()` for engineering. New group files:
  - `home/text.rs`: one font row and one alignment row reusing the `font.rs` and `paragraph.rs` controls, which become `pub(super)`, plus a launcher that runs `ui.inspector {tab: "format"}`.
  - `home/quick_insert.rs`: `insert.next`, `insert.connect`, `ui.insertPicker`, `ui.pane.patterns`.
  - `home/layout.rs`: the Design Layout group reached through a new accessor in `design/mod.rs`, so b6-ux's notation-aware Re-Layout menu shows here too.
  - `home/check.rs`: `validate.run`, and `ui.dock {tab: "problems"}` labelled "Problems".
- Engineering order: Clipboard, Text, Insert, Layout, Check, Arrange, Styles (`shape_styles::quick_styles` only, made `pub(super)`), Tools. Editing and Undo stay on the quick access toolbar.
- Use existing icons only: `layout`, `routeAround`, `check`, `problems`, `pattern`, `connector`, `plus`, `commands`, `taskPanes`.
- There is no Code group (b6-code, wave 4) and no Pin (no pin command exists); both are follow-ups.

**Builder and path glyph icons.**
- Today `master_preview` in the Shapes pane and the builder rows draw real outlines. But `icons::paint_kind` is used in three places: by the `/` picker (`insert_picker.rs` ~line 182), by the insertion popover (`canvas/interact/insertion.rs` ~line 325) and by the ribbon `Control::Gallery` (`ribbon/controls.rs` `gallery`). It draws only `m.kind`, so a path or builder glyph (kind `Freeform`) shows as a generic box.
- Add `icons::paint_master(p, r, &Master, c, a)`. It draws `m.path` (unit-square path, aspect handled like `paint_kind`) when present and otherwise calls `paint_kind`.
- Swap the three call sites to it.

## Engine additions (minimal; all in `crates/engine/src/cmd/template.rs`, tests in `template_tests.rs`)

   - Pass it as `project` to `resolve`. That gives the project's family variant when the pack has one, else the template's own. The project sheet is used only when the template has a sheet.
   - The `template.standards` prelude writes the given values. Without the param it behaves as today.
   - `template.preview` also returns `variant` and `sheet`.
   - Update both params docs.
   - Tests:
     - `flowchart.decision` with `{symbols: "jic", sheet: "ansi.b"}`: standards `jic` and `asme.b.landscape`, the page has no sheet, `undo_depth() == 1`.
     - `network.physical` with `{sheet: "asme.b"}`: page sheet ASME B.
     - `er.schema` with `{symbols: "iec"}`: variant `er.ie`, `standards.symbols == "iec"`.
     - Junk `standards` (`5`, `{symbols: "A B"}`, `{sheet: "x"}`) is rejected with `rev` and history unchanged.
2. **`pub fn resolved(id: &str, choices: &Choices, project: Option<&Standards>) -> Result<(String, String), EngineError>`**, a public wrapper of `resolve` through `lookup`. Test: for every shipped template it equals the `variant` and `sheet` that `template.new` reports with the same standards.
3. **`pub fn listing(audience: Option<&str>, pack: Option<&str>, query: Option<&str>) -> Vec<Value>`.** It is the body of `list`, which now calls it. Test: `template.list` equals `listing` for three filter sets.
