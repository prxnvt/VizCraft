# How existing tools serve engineers drawing schematics, and what engineers want

Research notes for VizCraft product design, 2026-10-19. Everything below is paraphrased from public documentation, vendor pages, forums and review sites; nothing is to be copied. Vendor pages are marketing and are flagged as such. The search budget ran out before a few minor items could be verified; those gaps are named in place.

## 1. Electrical CAD

**Symbol standards.** The serious tools treat the standard as a project-level library choice, not a per-symbol decision. EPLAN ships separate IEC/DIN/GOST and NFPA/JIC symbol libraries plus unlimited user libraries ([feature matrix, secondary](https://www.slideshare.net/slideshow/eplanfunction-overview/52923025)); one reviewer complains the NFPA symbols need constant modification ([Capterra](https://www.capterra.ca/reviews/152595/electric-p8)). AutoCAD Electrical advertises 65,000+ symbols and keeps JIC and older IEC libraries for legacy support ([Autodesk](https://www.autodesk.com/products/autocad-electrical/features)). SOLIDWORKS Electrical resellers list IEC, ANSI, JIS and GB symbol sets with a 500,000-part manufacturer database ([Hawk Ridge](https://hawkridgesys.com/solidworks-electrical-schematic)). SEE Electrical offers IEC, IEEE/NFPA, GOST and GB libraries ([IGE+XAO](https://www.ige-xao.com/en/?p=261904)). WSCAD points users to a portal of 1.4 million symbols and part data from 340 manufacturers ([WSCAD](https://www.wscad.com/wp-content/uploads/2018/10/10-good-reasons09-2018_EN196dpi.pdf)).

**Project structure.** EPLAN maps IEC/EN 81346 aspects onto identifier blocks: `=` higher-level function, `+` mounting location, `-` device, giving page names like `=AP+ST1/6` and device tags like `=AP+ST1-F6`; when an identifier is marked "use for structuring" it becomes a level of the page navigator tree ([EPLAN help: reference designations](https://www.eplan.help/help/platform/2.8/en-US/help/Content/htm/projectstructure_k_referenzkennzeichnung.htm), [identifier blocks](https://www.eplan.help/en-us/infoportal/content/Plattform/2.9/Content/htm/projectstructure_k_aufbaukennzeichnungsbl.htm), [object identifier](https://eplan.help/help/platform/2.8/en-us/help/content/htm/projectstructure_k_objektkennzeichen.htm)). WSCAD also structures data by function, location and product per DIN EN 81346 ([flyer](https://www.wscad.com/wp-content/uploads/2021/08/WSCAD-BuildingAutomation-Flyer-EN-2021_08.pdf)). AutoCAD Electrical uses a project of drawings with project-level and drawing-level property dialogs that set tag and wire-number formats ([replaceable parameters](https://help.autodesk.com/cloudhelp/2025/ENU/AutoCAD-Electrical/files/GUID-8F803D63-4390-4617-BC71-F68AE7545D97.htm)). KiCad uses one `.kicad_sch` file per sheet, hierarchical sheets, global labels that connect anywhere and hierarchical labels that connect to the parent's sheet pins ([KiCad 9 manual](https://docs.kicad.org/9.0/en/eeschema/eeschema.html)). QElectroTech splits a scheme into folios and provides folio-referencing elements that show where a conductor leaves and re-enters ([QET manual](https://download.qelectrotech.org/qet/manual_0.7/build/project/properties/new_folio/folio_referencing.html)).

**Wire numbering and device tagging.** AutoCAD Electrical numbers wires sequentially or by line reference, project-wide or only new wires, and composes tags from replaceable parameters such as family code, sheet, drawing and sequence (a relay on sheet 4 becomes `CR-4-25` under one pattern) ([wire tagging dialog](https://help.autodesk.com/cloudhelp/2027/ENU/AutoCAD-Electrical/files/GUID-47A01F82-0F25-4723-ACD6-C673C1B1826C.htm), [CAD Forum tip](https://www.cadforum.cz/en/parametric-labeling-numbering-in-autocad-electrical-tip15070)). Zuken E3.series lists configurable wire numbering with automatic signal updates ([datasheet](https://zuken.com/it/resource/datasheet-e3-series-schematic)); SEE Electrical numbers connections automatically in several formats ([IGE+XAO](https://ige-xao.com/en/us/see-electrical)); KiCad annotates reference designators as letter plus lowest unused number, optionally offset by sheet number times 100 or 1000 ([KiCad 9 manual](https://docs.kicad.org/9.0/en/eeschema/eeschema.html)).

**Cross references.** EPLAN, SOLIDWORKS Electrical and E3 all describe coil-contact cross references that update live from manufacturer part data ([EPLAN](https://eplan.com/us-en/products/eplan-electric-p8), [CADMicro matrix](https://www.cadmicro.com/wp-content/uploads/SOLIDWORKS-Electrical-Schematic-Matrix.pdf), [Zuken](https://zuken.com/us/product/e3series/electrical-schematic-design)). AutoCAD Electrical tracks parent and child contacts and lets you "surf" between cross-referenced arrows across drawings or in a hyperlinked PDF ([Autodesk](https://www.autodesk.com/products/autocad-electrical/features), [Arkance guide](https://emea.support.arkance.world/hc/hu/articles/36468977748498-AutoCAD-Electrical-2021-Fixing-Potential-Cross-Reference-Errors)). SEE Electrical makes cross references clickable in exported PDFs ([IGE+XAO](https://ige-xao.com/en/us/see-electrical)). QElectroTech uses a master element (holds the data, appears in the BOM) and linked slave elements ([QET manual](https://download.qelectrotech.org/qet/manual_0.7/build/element/cross_reference/cross_reference_master.html)).

**Terminal strips, cables, reports.** Terminal drawings generated from the live schematic are standard in SOLIDWORKS Electrical ([Hawk Ridge](https://hawkridgesys.com/solidworks-electrical-schematic)); E3 produces BOM, wire lists, cable schedules, terminal plans, PLC addressing and wire labels from the database and groups wires into multicores in the E3.cable module ([Zuken](https://www.zuken.com/en/product/e3series/design-and-documentation/)); EPLAN derives BOM, terminal and wire diagrams automatically and exports to Excel ([EPLAN](https://eplan.com/us-en/products/eplan-electric-p8)); SEE Electrical adds an SQL report designer in higher tiers ([IGE+XAO](https://www.ige-xao.com/en/?p=261904)). QElectroTech 0.100 (January 2026) added a terminal-strip item type with an editor that draws bridges and links ([release thread](https://qelectrotech.org/forum/viewtopic.php?id=3099), [changelog](https://raw.githubusercontent.com/qelectrotech/qelectrotech-source-mirror/0.100/ChangeLog)).

**Plot frames and title blocks.** EPLAN assigns a plot frame at project level, overridable per page, and title-block fields are placeholders for project or page properties inserted as special text in the frame editor ([page properties](https://www.eplan.help/help/platform/2.8/en-us/help/Content/htm/pagebrowsergui_k_eigenschaften.htm), [special texts](https://www.eplan.help/en-us/infoportal/content/Plattform/2.9/Content/htm/formeditorgui_h_sondertexteeinfuegen.htm)). QElectroTech has customisable title blocks with an extra free-text field ([QET manual](https://download.qelectrotech.org/qet/manual_0.7/build/folio/title_block/what_is.html)).

**Ladders and smart connection.** AutoCAD Electrical's ladder tool takes width, rung spacing, first reference number, increment and rung count; a rung dropped on a floating device breaks the wire across it, and "Retag Components" updates tags after line references change ([ladders](https://help.autodesk.com/cloudhelp/2025/ENU/AutoCAD-Electrical/files/GUID-4797FDE4-99EF-4E28-AC64-DA58390BA7B6.htm)). KiCad starts a wire automatically when you click an unconnected pin, adds junction dots where a wire starts or ends on another wire, and never connects crossing wires implicitly ([KiCad 9 manual](https://docs.kicad.org/9.0/en/eeschema/eeschema.html)). EPLAN's "autoconnecting" joins symbols placed in line ([EPLAN help](https://eplan.help/en-us/Infoportal/Content/Plattform/2.9/Content/htm/singlepole_h_stromlaufplaenezeichnen.htm)); Horizon EDA places junctions automatically and asks before merging two nets ([Horizon docs](https://docs.horizon-eda.org/en/v2.3.0/feature-overview.html)). SOLIDWORKS line-diagram symbols need a surrounding rectangle or wires cannot snap ([exercise 13](https://help.solidworks.com/2022/English/swelec/EW2D_EX13.htm)).

**Insert by typing.** EPLAN's symbol selection has a "direct entry" field that jumps to the matching symbol and previews its variants ([EPLAN help](https://eplan.help/en-us/Infoportal/Content/Plattform/2.9/Content/htm/singlepole_h_stromlaufplaenezeichnen.htm)); SOLIDWORKS Electrical filters the library as you type ([CATI](https://www.cati.com/?p=119297)); KiCad's chooser (hotkey `A`) matches name, keywords and description with wildcards ([KiCad 9 manual](https://docs.kicad.org/9.0/en/eeschema/eeschema.html)); LTspice places a resistor with `R`, opens the component picker with `F2` and draws wires with `W`/`F3` ([ADI shortcuts](https://www.analog.com/en/resources/technical-articles/ltspice-keyboard-shortcuts.html)).

**ERC/DRC.** KiCad's ERC reports incorrect and missing connections as markers; violations can be excluded from the ERC dialog, exclusions persist and show greyed, but cannot carry a note explaining why ([forum](https://forum.kicad.info/t/annotating-drc-exclusions/46006), [forum](https://forum.kicad.info/t/acknowledge-erc-errors/28151)). Altium compiles the project, draws a coloured squiggle under offending objects, pops a summary on hover, lists everything in a Messages panel, and lets you place a "No ERC" directive on a single net rather than disabling a rule globally ([signals with no load](https://altium.com/documentation/altium-designer/workspacemanager-err-signalswithnoloadsignals-with-no-load-ad), [No ERC](https://www.altium.com/documentation/altium-designer/schematic-no-erc)). AutoCAD Electrical has separate Drawing Audit (floating wire numbers, zero-length wires, bogus pointers) and Cross-reference Check commands ([command list](https://help.autodesk.com/cloudhelp/2025/ENU/AutoCAD-Electrical/files/GUID-33E21585-A333-42FF-AC86-9EE541B7FB77.htm)). LTspice has no ERC; a floating node surfaces as a "singular matrix" error at simulation time ([AllAboutCircuits](https://forum.allaboutcircuits.com/threads/ltspice-singular-matrix.45862/)).

**Praise and complaints.** EPLAN: Capterra ease-of-use 3.2/5, "steep learning curve", "poorly documented options", "training is a must"; a control.com engineer says drawings became more accurate after a three-day course than after three years in AutoCAD ([Capterra](https://www.capterra.com/reviews/152595/Electric-P8), [Gartner](https://ls.dmbx.aws.gartner.com/reviews/152595/electric-p8), [control.com](https://control.com/forums/threads/electrical-design-software.23115/post-131491), [EDAboard](https://www.edaboard.com/threads/46213)). AutoCAD Electrical: 4.6/5 but "sheer number of features makes it hard to master", slow startup, lines do not snap cleanly ([Capterra](https://www.capterra.com/p/179916/AutoCAD-Electrical/reviews/?page=2)); the forums are full of wire numbers that float off their wire after a plain Move, copies that split one wire into three numbers, and audits that fail to catch them ([floating wire numbers](https://forums.autodesk.com/t5/autocad-electrical-forum/floating-wire-nos/m-p/5362991), [wires not connected after copy](https://forums.autodesk.com/t5/autocad-electrical-forum/wires-not-connected-after-copy/m-p/10799411), [line references off by one](https://forums.autodesk.com/t5/autocad-electrical-forum/having-difficulty-with-line-references-and-wire-numbers/m-p/11328577)). The lesson is that wire numbers stored as graphics glued to lines are fragile; they must be properties of a net. KiCad: library management is the "biggest single pain point for beginners", default libraries are read-only, parts must be added twice (symbol and footprint), and "too much is hidden under the right mouse button" ([G2](https://www.g2.com/products/kicad-eda/reviews_and_filters), [Hackaday](https://hackaday.io/event/28713-the-state-of-kicad/discussion-98829), [PCBShopper](https://pcbshopper.com/kicad-reviews/), [forum](https://forum.kicad.info/t/too-much-stuff-is-hidden-under-context-sensitive-rmb/55204?page=2)). WSCAD reviewers praise the libraries and automatic cross-referencing ([Capterra](https://www.capterra.co.uk/software/1016750/wscad-electrix)).

## 2. Process and P&ID

**Tags.** AutoCAD Plant 3D / P&ID defines a tag format per class in Project Setup (base formats such as `Type-Number`, with expressions that acquire values from related objects, e.g. a line segment inherits `PipeLineGroup.Service` and `LineNumber`); the Assign Tag dialog shows the class, the format, the composed result and a list of tags already used so you can keep them unique ([tag format](https://help.autodesk.com/cloudhelp/2026/ENU/Plant3D-UserGuide/files/GUID-94841151-975B-425B-BC63-4D8CBE7EC7AA.htm), [assign tag](https://help.autodesk.com/cloudhelp/2017/ENU/Plant3D-UserGuide/files/GUID-DB8CC9F0-48B0-47DA-A4BE-51626D06D03D.htm), [class binding](https://help.autodesk.com/cloudhelp/2017/ENU/PNID/files/GUID-4B511EC8-A68C-48FE-90D2-71646B782273.htm)). Its symbol sets follow PIP, ISA, ISO, DIN and JIS ([Autodesk](https://help.autodesk.com/cloudhelp/2016/ENU/PNID/files/GUID-C7FAA5D1-7776-4E86-B19C-6EFBE71ED555.htm)). Visio's template auto-assigns an "intelligent tag number" per component and offers a Renumber command scoped to document, page or selection with start and interval per tag format; dropping a valve on a pipeline splits the pipe into two glued pieces and deleting it rejoins them ([Microsoft](https://support.microsoft.com/en-us/visio/create-a-p-id-or-pfd)). Lucidchart's P&ID shapes are "based on ISA S5" and a community thread notes there is no ISO 10628 library ([Lucid](https://lucid.co/diagram/p-and-id/symbols), [community](https://community.lucid.co/product-questions-3/what-is-standard-of-this-pid-symbols-1784)). None of the general tools compose an ISA-5.1 bubble from typed fields; the user types the whole tag. A third-party tool on SOLIDWORKS, SolidPlant P&ID, keeps a registry of tag numbers and warns on duplicates ([brochure](https://www.beacon-india.com/wp-content/uploads/2020/05/Brochure-SolidPlant-PID.pdf)); no SOLIDWORKS-branded P&ID feature list was found, only partners (Smap3D, SolidPlant, M4) ([Smap3D](https://mail.sfdesign.com.au/smap3d/pid-software), [M4 P&ID](https://www.cad-schroer.com/products/m4-pid-fx/features/)).

**Line numbering and off-page connectors.** Plant 3D treats an off-page connector as a line continuing on another drawing, marked with a TO/FROM prefix; the Line List shows start and end components across drawings ([glossary](https://help.autodesk.com/cloudhelp/2026/ENU/Plant3D-UserGuide/files/GUID-228D24D8-924A-408E-BF33-DEA066FA825C.htm), [line list](https://help.autodesk.com/cloudhelp/2026/ENU/Plant3D-UserGuide/files/GUID-0B00044E-0B8D-4CD4-B666-3DC1C5A00C75.htm)). Users report that out of the box "there is great inconsistency with the pipe line numbers" and that deriving the OPC number from the line only works without branches ([Hagerman](https://blog.hagerman.com/autocad-pid-and-autocad-plant-3d-pipe-line-numbers), [idea thread](https://forums.autodesk.com/t5/autocad-plant-3d-p-id-ideas/off-page-connectors-pair-numbering/idi-p/7658694)). AVEVA Diagrams (Visio-hosted) validates the whole drawing set for completeness and consistency, supports multi-sheet diagrams via off-page connectors, warns on unconnected connectors at open or sync, propagates pipe property changes to connected drawings, and has an audit that reconciles connector properties across drawings ([brochure](https://www.aveva.cn/content/dam/aveva/documents/brochures/Brochure_AVEVA_Diagrams_23-11.pdf.coredownload.inline.pdf), [OPC audit](https://docs.aveva.com/bundle/p-id/page/752113.html), [offsheet config](https://docs.aveva.com/bundle/p-id/page/751789.html), [line list rules](https://help.aveva.com/AVEVA_Diagrams/14.1/Diagrams/Piping_Instrumentation.06.36.html)).

**Data behind the drawing and validation.** Hexagon Smart P&ID is explicitly data-centric: the drawing is a view of the plant database, user-defined rules in a Rule Manager flag inconsistencies with error or warning symbols at the location, and equipment lists, line lists and simulation data can be imported to update the database ([Hexagon docs](https://docs.hexagonppm.com/r/en-US/Intergraph-Smart-P-ID-Help/11/174832), [design validation](https://hexagon.com/id/products/intergraph-smart-p-id-design-validation), [rule manager guide, old](https://www.scribd.com/document/700263213/RuleMgrUserGuide)). Plant 3D's validation settings include OPCs that do not continue on another drawing and annotations that drifted beyond a tolerance from their component ([validation settings](https://help.autodesk.com/cloudhelp/2017/ENU/Plant3D-UserGuide/files/GUID-3FDD798F-FB2A-432C-804E-7A616ABFB79A.htm), [error reference](https://help.autodesk.com/cloudhelp/2017/ENU/PNID/files/GUID-DF42724D-EB2E-497F-8A33-0E8C42C3D279.htm)). Visio's BOM is a Shape Report filtered on the component-tag property ([Microsoft](https://support.microsoft.com/en-us/visio/create-a-p-id-or-pfd)).

**Praise and complaints.** EdrawMax and SmartDraw score about 4.5/5 for ease of use, with complaints about support and billing rather than engineering depth; no independent review of their symbol compliance was found ([Capterra](https://www.capterra.com/p/82970/EDraw-Max/reviews), [G2](https://www.g2.com/compare/smartdraw-vs-wondershare-edrawmax), [AutomationForum](https://automationforum.co/11-best-pid-software-tools-for-process-design-engineers-in-2025/)). ConceptDraw sells P&ID as a solution-pack of vector symbols ([ConceptDraw](https://www.conceptdraw.com/How-To-Guide/pid-drawing-tool)). SmartDraw line-numbering details could not be verified before the search budget ran out.

## 3. Fluid power

Automation Studio's libraries are ISO 1219-1 and -2 compliant; a "spool designer" builds any directional-valve position when a standard symbol is missing; components carry default physical properties so a circuit simulates immediately, with pressure and flow readable at any point and levers operable during the run; diagnostics flag free connectors, redundant or overlapping lines and ISO non-compliance; BOMs update dynamically ([hydraulic](https://www.famictech.com/Products/Automation-Studio/Professional-Edition/Technologies/Hydraulic-Simulation), [pneumatic](https://www.famictech.com/Products/Automation-Studio/Professional-Edition/Technologies/Pneumatic-Simulation)). FluidSIM checks whether a connection is permissible while you draw, animates every multi-state component in simulation, and its manual has chapters on configuring directional control valves and cylinders, configurable symbols, current-path numbering with a switching-elements table, and terminal assignment diagrams ([control.com](https://control.com/technical-articles/electro-pneumatic-circuit-creation-and-simulation-using-fluidsim/), [FluidSIM help](https://documentation.help/fl_sim_h/fl_sim_h_19.htm), [FluidSIM 6 guide TOC](https://studylib.net/doc/27671572/fluidsim-manual-enus)); parts lists, hose lists and terminal diagrams are documented for the sister product FluidDraw, which also bundles an ISO 1219-1 neutral library and a DIN EN 60617 electrical library ([Festo](https://www.festo.com/x/fluiddraw-app), [manual](https://www.festo.com/fox/net/supportportal/Downloads/510802/561700/FluidDrawENGB.pdf)). HydraForce i-Design (free) has 1,000+ configurable ISO components, exports a BOM with quantity, configuration, parameters and orientation, prices the parts, lays out a 3D manifold that colours components red or orange when too close, and exports to Automation Studio for pressure-drop checks ([HydraForce](https://www.hydraforce.com/design-tools/i-design/)). SMC's online PneuDraw checks compatibility of adjacent components through defined connection parameters, generates a parts list alongside the drawing, and exports DXF/SVG/PDF plus TXT/CSV/XLS ([SMC](https://smc.eu/products/engineering-tools/pneumatic_circuits_drawing)); an older desktop program is drag-and-drop only ([SMC](https://www.smcworld.com/select/pcds/en-jp/index.html)).

## 4. Mechanical and general diagramming

Visio Professional's Engineering category offers Basic Electrical, Circuits and Logic, Fluid Power, Industrial Control Systems, Parts and Assembly Drawing, Piping and Instrumentation Design, Plumbing and Piping Plan, Process Flow Diagram, Systems, TQM and Work Flow; each asks for metric or US units and opens an unscaled portrait page; shapes glue through connection points whose endpoints turn red (or green for pipelines) when attached ([Microsoft](https://support.microsoft.com/en-us/visio/create-an-electrical-engineering-diagram), [template list](http://www.easypctraining.com.au/wp-content/uploads/Visio-Categories-and-Templates-List.pdf), [P&ID page](https://support.microsoft.com/en-us/visio/create-a-p-id-or-pfd)). draw.io has an Electrical library (circuits and racks) and a Process Engineering library with ISO shapes, both enabled through "More Shapes"; no pneumatic or hydraulic library was found ([drawio-app](https://drawio-app.com/engineering/)). MyDraw and ConceptDraw ship similar Process Engineering and Electrical libraries ([MyDraw](https://www.mydraw.com/shape-libraries-engineering-process-engineering), [ConceptDraw](https://www.conceptdraw.com/How-To-Guide/pid-drawing-tool)). Lucidchart's engineering libraries cover piping, instruments, valves, exchangers, vessels and pumps and allow SVG import for custom symbols ([Lucid](https://lucid.co/diagram/p-and-id/symbols)). Sheet-size and title-block offerings could not be verified before the budget ran out.

What engineers say is missing: in Visio, connection points on a wire did not stay attached when moved, and "Visio is clearly less robust than a schematic capture program" ([Visio Guy](https://visguy.com/vgforum/index.php?topic=2334.0)); wire numbers and an Excel wire list had no link to the drawing ([Visio Guy](https://visguy.com/vgforum/index.php?topic=6188.0)); a cable cannot be a sub-assembly, so it shows as several BOM lines ([Autodesk community](https://forums.autodesk.com/t5/autocad-electrical-forum/wiring-diagrams-with-cables-as-subassemblies-parts-that-will/td-p/8740595)); comparison sites (vendor-leaning) summarise it as no electrical data model that generates wire lists, interlocks or terminal plans, no industrial wire numbering, no manufacturer parts portal ([Gitnux](https://gitnux.org/best/wiring-diagram-software/), [ConceptViz](https://conceptviz.app/blog/best-electrical-wiring-diagram-software-guide), [IMD](https://industrialmonitordirect.com/blogs/knowledgebase/visio-for-industrial-pid-and-control-drawing-add-ins)). Third-party stencil vendors fill the gap with shape-data-driven BOMs ([Paul Herber](https://www.paulherber.co.uk/visio-electrical/)). A QElectroTech forum thread shows users assembling electrical, pneumatic and hydraulic libraries themselves because packs mix standards ([QET forum](https://qelectrotech.org/forum/viewtopic.php?pid=16048)).

## 5. Simulation and analysis adjacency

KiCad integrates ngspice with AC, DC, operating-point, transient and custom runs and a probe tool; users still keep a separate simulation schematic and fight vendor model syntax ([KiCad](https://www.kicad.org/discover/spice/), [ngspice tutorial](https://ngspice.sourceforge.io/ngspice-eeschema.html), [forum](https://forum.kicad.info/t/kicad-and-spice-simulations/12973)). EasyPower integrates short circuit, power flow, coordination and the database "under control of the interactive one-line"; ETAP and SKM both run load flow, short circuit, IEEE 1584 arc flash and coordination off the one-line, and ETAP supports unlimited one-line presentations and alternative symbol sets per device type ([EasyPower help](https://help.easypower.com/ezp/10.5/Content/01_EasyPower/Introduction.htm), [Bentley](https://www.bentley.com/products/easypower), [comparison](https://engineersuniverse.com/studios/electrical/etap-vs-skm-power-system-analysis-comparison), [ETAP tip](https://es.scribd.com/document/341794405/ETAP-TIP-001-1)). i-Design hands pressure-drop checks to Automation Studio ([HydraForce](https://www.hydraforce.com/design-tools/i-design/)). Ansys medini generates fault trees from Simulink models; Simulink Fault Analyzer does fault injection, and MATLAB has no native FTA ([Ansys](https://ansyshelp.ansys.com/public/Views/Secured/medini/v25202/en/medini_analyze_ug/sec_deprecated_features.html), [MathWorks](https://au.mathworks.com/products/simulink-fault-analyzer.html), [MathWorks Answers](https://www.mathworks.com/matlabcentral/answers/663803-how-to-do-a-probabilistic-analysis-in-simulink)). Planar linkage tools (OpenLinkSim, Pyslvs-UI, pylinkage) compute position, velocity and force and the Grübler mobility count `M = 3(n-1) - 2j1 - j2` ([OpenLinkSim](https://b2find.eudat.eu/dataset/651e14f7-15a5-5ec5-9e9f-133aee5b53fd), [Pyslvs](https://pypi.org/project/pyslvs-ui/21.5.0/), [pylinkage](https://pylinkage.readthedocs.io/en/latest/), [formula](https://www.firgelliauto.com/es/blogs/mechanisms/mechanism-engineering)). SKiDL shows the minimum useful "engine": a netlist plus an ERC for common mistakes ([SKiDL](https://github.com/devbisme/skidl)).

Minimal analysis features that recur across these tools and that a diagramming tool can offer without a solver: netlist extraction, net highlight and connectivity trace, ERC (unconnected pins, driver conflicts, duplicate tags, floating nodes), loop and OPC completeness, BOM with manufacturer parts, cable and wire length sums, pressure-drop or load placeholders that hand off to an external solver, and state-machine or ladder stepping.

## 6. Interaction patterns worth adopting

- Wire starts from an unconnected pin on click; junction dots appear automatically where a wire ends on a wire; crossings never connect implicitly ([KiCad](https://docs.kicad.org/9.0/en/eeschema/eeschema.html), [Horizon](https://docs.horizon-eda.org/en/v2.3.0/feature-overview.html)).
- Ladder with rails, rung spacing, first reference and increment; devices dropped on a rung break the wire and inherit the reference in their tag ([Autodesk](https://help.autodesk.com/cloudhelp/2025/ENU/AutoCAD-Electrical/files/GUID-4797FDE4-99EF-4E28-AC64-DA58390BA7B6.htm)).
- Cross-reference arrows you can "surf" between sheets, and clickable references in exported PDF ([Arkance](https://emea.support.arkance.world/hc/hu/articles/36468977748498-AutoCAD-Electrical-2021-Fixing-Potential-Cross-Reference-Errors), [IGE+XAO](https://ige-xao.com/en/us/see-electrical)).
- Net highlight as a colour override on click, a Navigator panel that lists a net's pins, labels, ports and sheet entries, and Ctrl+Alt hover for jumping between sheets ([Altium net colours](https://altium.com/kr/documentation/altium-designer/sch-cmd-netcolorsnetcolors-ad), [Navigator](https://www.altium.com/documentation/altium-designer/sch-pcb/navigator-panel), [connectivity](https://www.altium.com/documentation/altium-designer/creating-circuit-connectivity-schematics)).

## 7. Open-source tools and text interfaces

- **KiCad**: right about the grid discipline, automatic junctions, symbol search and ERC with exclusions; wrong, by its own users, about library onboarding and context-menu discoverability (sources in section 1).
- **QElectroTech**: folios, folio-reference elements, master/slave cross references, customisable title blocks and the new terminal-strip editor; small team, Qt5 era UI, 0.200 is the Qt6 port ([release thread](https://qelectrotech.org/forum/viewtopic.php?id=3099)).
- **Horizon EDA**: net-aware editing with a confirmation on net merge, auto junctions, text that re-orients to stay readable, spacebar command palette, single-key and chorded shortcuts, multithreaded rule-based DRC ([docs](https://docs.horizon-eda.org/en/v2.3.0/feature-overview.html)).
- **LibrePCB**: a library manager that needs no Git, renames that do not break references, self-contained projects, files optimised for version control, one netlist shared by schematic and board; admits no hierarchical sheets and a smaller catalogue ([LibrePCB](https://librepcb.org/compare/)).
- **FreeCAD TechDraw**: templates are SVG files whose editable text fields (title, scale, sheet, drawing number) are marked with a `freecad:editable` attribute and filled from the UI, Python or an autofill tool in 1.0 ([Templates](https://wiki.freecad.org/TechDraw_Templates), [HowTo](https://wiki.freecad.org/TechDraw_TemplateHowTo)).
- **OMEdit**: libraries browser tree, drag onto Diagram or Icon view, explicit connect mode drawn connector to connector ([OpenModelica](https://openmodelica.org/doc/OpenModelicaUsersGuide/1.21/omedit.html)). **Xcos**: palette browser plus superblocks that open a nested diagram with numbered ports and optional masks ([Scilab](https://help.scilab.org/doc/6.0.1/en_US/SUPER_f.html), [tutorial](https://script.spoken-tutorial.org/index.php/Scilab/C4/Super-Blocks-in-Xcos/English)).
- **draw.io**: has electrical and ISO process shapes but no net semantics ([drawio-app](https://drawio-app.com/engineering/)). **Mermaid**: no electrical diagram type; the only "circuit" proposal is for quantum circuits ([weekly report](https://buttondown.com/weekly-project-news/archive/weekly-github-report-for-mermaid-july-20-2026/)).
- **Text syntaxes**: CircuiTikZ draws a path with elements inline, e.g. `\draw (0,0) to[R=$R_1$] (2,0);` ([manual](https://ftp.math.utah.edu/pub/texlive/Contents/live/texmf-dist/doc/latex/circuitikz/circuitikzmanual.pdf), [tutorial](https://latex-tutorial.com/?p=642)); Circuit_macros are m4 macros that evaluate to pic, TikZ or SVG ([CTAN](https://ctan.org/pkg/circuit-macros), [examples](https://ece.uwaterloo.ca/~aplevich/Circuit_macros/html/examples.pdf)); Schemdraw chains elements with direction methods, `elm.Resistor().right().label('1Ω')` ([docs](https://schemdraw.readthedocs.io/)); WaveDrom's WaveJSON is a `signal` array of `{name, wave}` objects where each character is one clock step, with `data`, `node` and `edge` for buses and arrows ([schema](https://github.com/wavedrom/schema/blob/master/WaveJSON.md), [repo](https://github.com/wavedrom/wavedrom)); netlistsvg lays out a Yosys JSON netlist with ELK using digital or analog skins ([netlistsvg](https://github.com/nturley/netlistsvg)); SKiDL describes connectivity in Python (`r1[1] += vin`), runs ERC and emits a netlist ([SKiDL](https://github.com/devbisme/skidl)). The common thread: elements and nets are first-class, geometry is derived, and a layout engine draws the picture, which is exactly the shape an MCP agent interface wants.

## Recommendations for VizCraft (synthesis)

Prioritised within each group; "day one" items first.

**Palette and templates**
1. One standard per project (IEC 60617 or NFPA/IEEE, ISA-5.1, ISO 1219) chosen at project creation and switchable later, with the pack mapping each semantic element to a symbol so a switch redraws without re-placing.
2. Templates named the way engineers look for them: Electrical Schematic (ladder and IEC styles), One-Line, Control Panel, P&ID, PFD, Hydraulic, Pneumatic, Block Diagram, Part and Assembly, each opening a scoped palette.
3. Type-to-insert: a chooser matching name, keyword and description with variant previews, plus single-key placement for the twenty most common symbols.
4. Property-driven variants: contact type, pole count, valve positions, ways, actuators and returns chosen in the Inspector, including a parametric directional-valve builder.

**Canvas interaction**
5. Fixed modular symbol grid per notation pack, with pins only on grid, and orthogonal wires by default.
6. Click a free pin to start a wire; wire ends glue to pins; automatic junction dots where a wire ends on a wire; crossings never connect; confirm before merging two named nets.
7. Net highlight on hover or click, with a Navigator listing every pin, label and off-sheet reference on the net.
8. Ladder tool with rails, rung spacing, first reference and increment; devices dropped on a rung split the wire and inherit the rung reference.
9. Drop a valve or instrument on a pipe to split and glue it; delete to heal.
10. Keyboard rotate and mirror, Escape-free tool cycling, and a spacebar or slash command palette.

**Sheet and project structure**
11. Project tree keyed by function and location (IEC 81346 style `=`, `+`, `-`) that also drives page naming and the tag composition.
12. Plot frames with sheet zones and title blocks whose fields bind to project and page properties, overridable per page; sheet navigator with thumbnails.
13. Off-sheet references that are one object seen twice: clickable arrows that navigate, and a validation that both ends exist.
14. Tags and wire numbers as properties of model objects, never graphics glued to lines, with format rules per class (`CR-{sheet}-{rung}`, `{letters}-{loop}`) and a uniqueness check.

**Data and reports**
15. Live tables in the bottom dock for BOM, wire list, cable schedule, terminal strip, line list and instrument index, filterable, editable where the field is user-owned, exportable to CSV and XLSX.
16. Manufacturer part on a device drives contact availability, pin names and BOM lines; a cable is one part with many wires.
17. Cross references (coil to contacts, master to slaves) computed from the model and rendered at both ends.

**Validation and analysis**
18. Problems pane ERC/DRC: unconnected pins, floating nets, duplicate tags, missing off-sheet partner, annotation drift, single-ended OPC, ISA tag malformed; squiggle on the object, hover summary, click to jump.
19. Per-object suppression with a required reason, persisted and listed.
20. Netlist export (KiCad-style and JSON) and a connectivity trace command; cable length sums and pressure-drop or load placeholders that hand off to external solvers.

**Agent and text interface**
21. A text form where elements and nets are first-class and layout is derived (Schemdraw and SKiDL style), so an MCP agent can say "add a 3-pole contactor K1 between rungs 12 and 14" and the layout engine places it.
22. Every ribbon command is an MCP tool with the same name, returning the Problems delta so agents can self-check after each edit.
23. Importers for KiCad netlist, WaveJSON and CSV part lists, so agents can bring in existing engineering data instead of redrawing it.
